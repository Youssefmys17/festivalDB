Donne les requêtes d'insertion permettant de remplir la base de données festivalDB dont le modèle relationnel est le suivant :

- Association (numeroSIREN, nomAssociation, emailAssociation) — Clé primaire : numeroSIREN
- Festival (nomFestival) — Clé primaire : nomFestival
- Site (nomSite, adresseSite, communeSite, capaciteMaxSite) — Clé primaire : nomSite
- Artiste (nomArtiste, paysOrigineArtiste, genreMusical, emailContactArtiste) — Clé primaire : nomArtiste
- Acheteur (emailAcheteur, nomAcheteur, prenomAcheteur, telephoneAcheteur) — Clé primaire : emailAcheteur
- Edition (numeroEdition, dateDebutEdition, dateFinEdition, #nomFestival, #nomSite) — Clé primaire : numeroEdition
- Scene (nomScene, capaciteScene, #nomSite) — Clé primaire : nomScene
- Jour_de_Festival (dateJourFestival, #numeroEdition) — Clé primaire : dateJourFestival
- Commande (referenceCommande, dateCommande, statutCommande, statutPaiement, datePaiement, #numeroEdition, #emailAcheteur) — Clé primaire : referenceCommande
- Ligne_de_Commande (#referenceCommande, numeroLigneCommande, typeBillet, prixUnitaire, quantite, #dateJourFestival) — Clé primaire composée : (referenceCommande, numeroLigneCommande)
- Organiser (#numeroSIREN, #numeroEdition) — Clé primaire composée : (numeroSIREN, numeroEdition)
- Jouer (#nomArtiste, #nomScene, #dateJourFestival, heureDebutConcert, heureFinConcert, montantCachet) — Clé primaire composée : (nomArtiste, nomScene, dateJourFestival)

Les clés primaires sont précisées après chaque relation (simples ou composées). Les clés étrangères sont identifiées par les #, et ont le même nom que les clés primaires auxquelles elles font référence.

Il doit y avoir un volume conséquent et cohérent de données :
- 3 lignes pour la table Association,
- 1 ligne pour la table Festival ('Echoes du Parc'),
- 2 lignes pour la table Site (inspirées de lieux réels comme le Domaine National de Saint-Cloud et le Val de Moine à Clisson),
- 3 lignes pour la table Edition (2024, 2025 et 2026),
- 6 lignes pour la table Scene réparties sur les sites (avec capaciteScene <= capaciteMaxSite du site correspondant),
- 9 lignes pour la table Jour_de_Festival (3 journées consécutives par édition comprises entre dateDebutEdition et dateFinEdition),
- 18 lignes pour la table Artiste provenant de pays et genres musicaux variés (dont 2 artistes n'ayant encore aucun concert programmé),
- 5 lignes pour la table Organiser (certaines éditions étant co-organisées par plusieurs associations),
- 32 lignes pour la table Jouer (sans aucun chevauchement horaire entre deux concerts sur une même scène le même jour, ni pour un même artiste le même jour, et sur une scène appartenant bien au site de l'édition du jour concerné),
- 20 lignes pour la table Acheteur (dont 2 acheteurs inscrits sans commande passée),
- 28 lignes pour la table Commande réparties sur les 3 éditions avec différents statuts de commande et de paiement,
- 45 lignes pour la table Ligne_de_Commande (chaque commande ayant au moins une ligne numérotée à partir de 1 ; les billets 'PassFestival' ont dateJourFestival à NULL tandis que les billets 'Journee' référencent une dateJourFestival appartenant à l'édition de la commande).

Les clés étrangères doivent faire référence aux clés primaires existantes : donne les lignes en commençant par remplir les tables dans lesquelles il n'y a pas de clés étrangères (Association, Festival, Site, Artiste, Acheteur), puis les tables dans lesquelles les clés étrangères font référence à des clés primaires des tables déjà remplies (Edition, Scene, Jour_de_Festival, Commande, Ligne_de_Commande, Organiser, Jouer).

Les données doivent respecter les contraintes de validation suivantes :
ALTER TABLE Association
    ADD CONSTRAINT chk_association_siren_format CHECK (numeroSIREN LIKE '_________'),
    ADD CONSTRAINT chk_association_nom_non_vide CHECK (nomAssociation <> ''),
    ADD CONSTRAINT chk_association_email_format CHECK (emailAssociation LIKE '%_@_%._%');
ALTER TABLE Festival
    ADD CONSTRAINT chk_festival_nom_non_vide CHECK (nomFestival <> '');
ALTER TABLE Site
    ADD CONSTRAINT chk_site_capacite_intervalle CHECK (capaciteMaxSite BETWEEN 100 AND 999999),
    ADD CONSTRAINT chk_site_adresse_commune_non_vides CHECK (adresseSite <> '' AND communeSite <> '');
ALTER TABLE Edition
    ADD CONSTRAINT chk_edition_annee_intervalle CHECK (numeroEdition BETWEEN 1990 AND 2100),
    ADD CONSTRAINT chk_edition_dates_coherentes CHECK (dateFinEdition >= dateDebutEdition);
ALTER TABLE Scene
    ADD CONSTRAINT chk_scene_nom_non_vide CHECK (nomScene <> ''),
    ADD CONSTRAINT chk_scene_capacite_intervalle CHECK (capaciteScene BETWEEN 50 AND 999999);
ALTER TABLE Artiste
    ADD CONSTRAINT chk_artiste_nom_pays_non_vides CHECK (nomArtiste <> '' AND paysOrigineArtiste <> ''),
    ADD CONSTRAINT chk_artiste_genre_valide CHECK (genreMusical IN ('Rock', 'Metal', 'Electro', 'Pop', 'Indie', 'Hip-Hop', 'Punk', 'Jazz-Fusion', 'Folk', 'Alternative')),
    ADD CONSTRAINT chk_artiste_email_format CHECK (emailContactArtiste LIKE '%_@_%._%');
ALTER TABLE Jouer
    ADD CONSTRAINT chk_jouer_horaires_coherents CHECK (heureFinConcert > heureDebutConcert),
    ADD CONSTRAINT chk_jouer_cachet_positif CHECK (montantCachet >= 0);
ALTER TABLE Acheteur
    ADD CONSTRAINT chk_acheteur_email_format CHECK (emailAcheteur LIKE '%_@_%._%'),
    ADD CONSTRAINT chk_acheteur_identite_non_vide CHECK (nomAcheteur <> '' AND prenomAcheteur <> ''),
    ADD CONSTRAINT chk_acheteur_telephone_format CHECK (telephoneAcheteur LIKE '0_________' OR telephoneAcheteur LIKE '+%');
ALTER TABLE Commande
    ADD CONSTRAINT chk_commande_reference_masque CHECK (referenceCommande LIKE 'CMD-%'),
    ADD CONSTRAINT chk_commande_statut_valide CHECK (statutCommande IN ('en_attente', 'confirmee', 'annulee')),
    ADD CONSTRAINT chk_commande_statut_paiement_valide CHECK (statutPaiement IN ('en_attente', 'paye', 'refuse', 'rembourse')),
    ADD CONSTRAINT chk_commande_coherence_paiement CHECK ((statutPaiement IN ('en_attente', 'refuse') AND datePaiement IS NULL) OR (statutPaiement IN ('paye', 'rembourse') AND datePaiement IS NOT NULL AND datePaiement >= dateCommande));
ALTER TABLE Ligne_de_Commande
    ADD CONSTRAINT chk_ligne_numero_intervalle CHECK (numeroLigneCommande BETWEEN 1 AND 999),
    ADD CONSTRAINT chk_ligne_type_billet_valide CHECK (typeBillet IN ('Journee', 'PassFestival')),
    ADD CONSTRAINT chk_ligne_prix_positif CHECK (prixUnitaire > 0),
    ADD CONSTRAINT chk_ligne_quantite_positive CHECK (quantite BETWEEN 1 AND 999);

Assure-toi que les noms et prénoms des acheteurs ainsi que les artistes font référence à des origines variées et sont mixtes.
